eRT on Sfera Labs Strato Pi Max — Setup Guide

About Sfera Labs and the Strato Pi Range Sfera Labs produces a range of industrial Raspberry Pi platforms designed for automation, building management, and edge computing. Their products combine the accessibility of open-hardware Raspberry Pi compute with hardened industrial I/O and enclosures suited to DIN-rail and panel mounting. Key Sfera Labs product families supported by inxware eRT: Strato Pi Max — Industrial controller built on Raspberry Pi CM4 or CM5. Dual Ethernet, Wi-Fi, Bluetooth 5.0. Up to four expansion slots, each providing seven-channel industrial digital I/O, quad RS-422/485, 24-bit ADC/DAC, and optional LTE (M.2). Base board includes hardware watchdog, UPS power management, dual SD card, USB power control, and an accelerometer/gyroscope. The primary target for this eRT build. Strato Pi Plus — Industrial Raspberry Pi 4 or 5 edge server, DIN rail mounted, 10–50 V DC input, multi-protocol connectivity. Strato Pi CAN — Server variant adding CAN bus and RS-485 interfaces. Strato Pi UPS — Server with integrated UPS, RS-232, and RS-485. Iono Pi Max v2 — Industrial PLC with digital and analog inputs, NO/NC relays, UPS, RS-232/485, and CAN — ideal for I/O-heavy automation tasks. Iono Pi v3 — Raspberry Pi 4 or 5 I/O module (PLC) with analog inputs, relays, and GPIO for lighter automation workloads. Exo Sense Pi — Multi-sensor module providing temperature, humidity, air quality, and light intensity — a natural companion for edge-AI inference with eRT. All Sfera Labs hardware runs standard Raspberry Pi OS (Debian-based), so inxware eRT installs from a single .deb package with no custom kernel or vendor toolchain required. Why inxware eRT on Sfera Labs Hardware? inxware eRT provides a rapid roadmap from single-threaded Python demos to rock-solid event-driven C/C++ speed IoT and edge-AI implementations, while providing the no-code approach demanded by automation and building-management engineers. On Sfera Labs hardware this means: — Wire up industrial I/O, RS-485 buses, analog sensors, and LTE modem connectivity directly in the eRT no-code function-block editor. — Drop in pre-built machine-learning inference blocks targeting the Raspberry Pi NPU (CM5) or TFLite CPU inference without writing a line of C. — When performance headroom matters, replace any function block with a C/C++ implementation — the same block ports and parameters, no protocol change, no re-wiring of the application graph. — The hardware watchdog, UPS state, and dual SD failover provided by the Strato Pi Max are all exposed as native eRT function blocks, making fault-tolerant field deployments straightforward. 1. Prepare Your Raspberry Pi CM4 or CM5 Flash your Compute Module with Raspberry Pi OS (64-bit) based on Debian 13 (trixie) using the official Raspberry Pi Imager: https://www.raspberrypi.com/software/ Refer to the Sfera Labs documentation for CM4/CM5 flashing and carrier board boot configuration: https://sferalabs.cc/ 2. Install eRT on Your Strato Pi Max Open a terminal on the device and run: cd ~/Downloads Download the Debian package: wget https://appland.inxware.io/downloads/appland/runtimes/sferalabs/SferaLabs-StratoPiMax-Debian-13-64bit.deb Install the package: sudo apt install ./SferaLabs-StratoPiMax-Debian-13-64bit.deb 3. Run eRT Run eRT from the terminal: /opt/ehs/bin/ehs.exe
