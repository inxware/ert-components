LoRaWAN end-device modem driver.

LoRaWAN is a long-range, low-power wide-area network protocol built on the LoRa physical layer. End devices transmit small payloads (typically < 256 bytes) over many kilometres at sub-GHz ISM frequencies (EU868, US915, AS923, …) with a duty cycle of seconds to minutes. The architecture is “star-of-stars”: end devices broadcast to one or more gateways, which forward every received frame over IP to a LoRaWAN Network Server (LNS). The LNS deduplicates, decrypts, runs MAC-layer logic and hands the application payload off to your application server.

To use this block in production you need three things outside of the device itself:

  1. A LoRaWAN gateway within radio range — either operate one yourself (e.g. a RAK / MikroTik / Kerlink concentrator) or rely on coverage from a community / commercial network.
  2. An account on a LoRaWAN Network Server. Common options are The Things Network / The Things Industries (free community + paid hosted), AWS IoT Core for LoRaWAN (managed, integrates with AWS IoT rules), or self-hosting an open-source LNS such as ChirpStack. Other commercial offerings include Actility ThingPark, Senet and Loriot.
  3. The device credentials registered on that LNS. For OTAA you need AppKey and AppEui (JoinEUI) plus the device's DevEui; for ABP you need NwkSKey, AppSKey and DevAddr. The device-side region, sub-band and RX2 settings configured here must match what the LNS expects for your gateway.

This function block drives an external LoRaWAN modem (e.g. Wio-E5, RAK3112) over UART or another transport configured in the target HAL. It supports class A / B / C operation, OTAA and ABP join, runtime data-rate / TX-power / class changes, MAC-layer link checks and a status query for diagnostics.

A typical flow is: configure the device-identity parameters (or override them on the input ports), trigger join, wait for ok (connect_cb), then use send to push uplinks and listen on received for downlinks. Most start ports are non-blocking — they only confirm the request was queued (--) or the modem is already busy (busy); the real result arrives later on the matching _cb finish port (ok / failed / done).

Behaviour that varies by target: AutoJoin scheduling, sub-band selection, link-margin reporting and runtime TX-power adjustment may be ignored on modems that do not expose them — the corresponding callback still fires ok in that case. See the target HAL implementation for the authoritative behaviour matrix.

Each command port (connect, send, reset, status, set, getLength, disable, set_class, set_tx_power, link_check) has a synchronous “request accepted” finish (--) and a busy finish that fires immediately when the modem cannot accept a new command. The eventual result is delivered later on a separate finish port that belongs to the matching _cb callback function (ok / failed / done) together with any returned data.

In Ev.
join Initiate a join to the LoRaWAN network. In OTAA mode the modem performs a Join procedure with the network server; in ABP mode the keys are loaded and the device is marked joined.
send Send an uplink message. payload (hex string), fport and confirm select the data, frame port and confirmation mode. Must be joined first.
reset Reset the LoRaWAN modem. Drops any current session; a fresh join is required afterwards.
status Query the modem for status (DevEui, link margin, gateway count, current TX power, current DR, etc.). Result is delivered on the ok (get_statusData_cb) finish port.
set Apply a new data-rate index (read from DR) at runtime. Has no effect when ADR is on (the network controls DR).
getLength Query the modem for the current maximum payload length (depends on Region, DR and any pending MAC commands). Result delivered on ok (get_payload_length_cb).
disable Leave the network and disable the radio. Following disabled, no uplinks or downlinks are processed until join is fired again.
set_class Change the device class (A / B / C) at runtime without a full rejoin. Class read from class input port. Must be joined.
set_tx_power Change the TX-power index at runtime. Power index read from txPwr. Must be joined.
link_check Schedule a LoRaWAN LinkCheckReq MAC command. The next uplink piggybacks the request; the network's LinkCheckAns reply yields link margin and gateway count via the link_check_cb finish ports.
Data In
region (join) Override the Region parameter for this and subsequent joins. Integer enumeration as listed under Region.
ADR (join) Override the ADR parameter at join time. When true, the modem requests ADR control from the network; the DR setting is ignored.
appKey (join) OTAA AppKey override. Used only when Mode = 0 (OTAA). 32 hex characters [0-9A-F].
appEui (join) OTAA AppEui (Join EUI) override. Used only when Mode = 0 (OTAA). 16 hex characters.
nwkSKey (join) ABP Network Session Key override. Used only when Mode = 1 (ABP). 32 hex characters.
appSKey (join) ABP Application Session Key override. Used only when Mode = 1 (ABP). 32 hex characters.
devAddr (join) ABP DevAddr override. Used only when Mode = 1 (ABP). 8 hex characters. (Distinct from the OTAA-assigned DevAddr returned on the DevAddr output port.)
miscOpt (join) Optional vendor-specific configuration string passed through to the modem driver at join. Format and meaning are HAL-defined (currently a no-op on the WIO-E5 backend).
class (join) Override the Class parameter for this join. Integer: 0 = A, 1 = B, 2 = C.
confirm (send) Send as a confirmed (true) or unconfirmed (false) uplink. Confirmed messages trigger acknowledgements and use the Retry count; unconfirmed messages use the Repeat count.
fport (send) LoRaWAN application frame-port number (1..223) for the uplink.
payload (send) Uplink payload as an even-length hex string, e.g. "0AAB34". Length must not exceed the modem's current maximum payload (see getLength).
DR (set) New data-rate index for set. Same encoding as the DR parameter. Ignored when ADR is on.
class (set_class) New device class for set_class: 0 = A, 1 = B, 2 = C.
txPwr (set_tx_power) New TX-power index for set_tx_power. Same encoding as the TxPower parameter (0 = max EIRP).
Data Out
DevAddr (connect_cb) Network-assigned DevAddr after a successful OTAA join. For ABP joins this echoes the devAddrABP input.
errno (connect_cb) Result code from the join attempt. 0 = OK; non-zero values are the LoRaWAN API errnos listed at the bottom of this section.
message (received) Downlink payload as a hex string.
fport (received) LoRaWAN frame-port number on which the downlink arrived.
lnkStat (received) Per-frame link status as a JSON string.

{"wt": 1 ,"rssi": -106 ,"snr": 6.00 }

rssi (received) Received signal strength indicator (dBm) of the last downlink frame.
snr (received) Signal-to-noise ratio (dB) of the last downlink frame.
rxwin (received) Receive window index (1 or 2) in which the last downlink was received.
errno (send_msg_cb) Result code from the most recent send attempt. 0 = OK; non-zero values use the LoRaWAN API errno table at the bottom of this section.
status (get_statusData_cb) Modem-specific status payload as a JSON string (e.g. RTC, temperature, voltage). Schema depends on the target modem.
devEui (get_statusData_cb) The 64-bit Device EUI of this end device, as a hex string.
linkMargin (get_statusData_cb) Link margin in dB from the most recent LinkCheckAns response (cached by the modem). For a fresh value, trigger link_check.
gateways (get_statusData_cb) Number of gateways that received the last link-check uplink (cached). For a fresh value, trigger link_check.
txPower (get_statusData_cb) Current TX-power index reported by the modem.
currentDR (get_statusData_cb) Current data-rate index in use (updated by ADR or set).
len (get_payload_length_cb) Current maximum payload length in bytes for the active region / DR.
linkMargin (link_check_cb) Fresh link margin (dB) returned by the network in LinkCheckAns.
gateways (link_check_cb) Fresh gateway count from the network's LinkCheckAns.
