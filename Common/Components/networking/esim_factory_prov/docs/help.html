Installs a pre-built eSIM profile package over a local link, with no network on the device.

For provisioning on a production line. The factory's equipment obtains a profile package already bound to this specific eSIM and streams it in through this block. The device itself needs no network connection at all.

Process: ReadEID and give the EID to the equipment, which requests a package for that chip; then Begin, PushSeg once per segment in order, then Commit. Commit reports the ICCID installed, which the eSIM Profiles block then enables.

No offset, and no retry of a single segment. The eSIM sequences segments by block number and reassembles by concatenation, so they must arrive in order and exactly once - there is no addressing and no seeking. Each segment's authentication code is chained to the previous one, so a rejected segment cannot be re-sent: Abort and restart the whole package.

Do not add a checksum. Every segment carries a cryptographic authentication code verified inside the eSIM, and nothing in this path holds the keys to forge one - so corruption introduced by the equipment, the link or this device fails that check. An application checksum would catch nothing extra and would imply a guarantee it does not give.

The package is never stored. Segments are decoded, passed to the eSIM and wiped; nothing reaches the filesystem, so no subscription material outlives provisioning.

Requires an eSIM chip and a vendor-supplied local install path. No currently supported target has either, so every operation reports not-supported (errCode 13).

Ports Top ↑ Misc ↓ Params ↑
In Ev.
ReadEID Read the eSIM's EID. Give this to the factory equipment so it can request a package bound to this specific chip - the step that has no equivalent in a remote download, where the eSIM presents its own EID inside the session and the application never sees it.
Begin Open an install session on the eSIM, ready to receive segments.
PushSeg Push one segment of the package. Segments must be pushed in order and exactly once.
Commit Finish the install and ask the eSIM to verify and store the profile.
Abort Discard the install session and wipe buffers. Safe to trigger when no install is running, which is what makes it usable as a timeout action.
Data In
segData One segment, hex encoded, because a string port is NUL-terminated and cannot carry raw binary. How many bytes fit per push is a platform property - a hex segment costs two characters per byte - and is not the same as the eSIM's own transport block size; the driver reassembles.
segLen Optional. The number of BYTES the caller believes it is sending. If connected, the decoded segment must match it or the push is rejected. This is a framing check, not a checksum: a string port is fixed width, so an over-long segment is truncated SILENTLY and the eSIM would then reject it as an authentication failure - pointing at a corrupt package when the real fault is splitting on the wrong size. Leave unconnected to trust the decoded length.
Data Out
EID The eSIM's EID, 32 decimal digits. Not secret: it identifies the chip and the factory needs it in the clear.
errCode Reason the EID read failed. See the enumeration at the foot of this table.
maxSegLen Largest segment, in BYTES, that may be pushed in one PushSeg call - split the package on this figure. It is the SMALLER of two independent limits: what the eSIM accepts, and what this device's port can carry (hex costs two characters per byte, so an MCU target is typically the binding one). Reads 0 when the EID read failed, meaning there is no usable path - never a plausible size you could split against in vain.
errCode Reason the session could not be opened. See the enumeration at the foot of this table.
errCode Reason the push failed. See the enumeration at the foot of this table.
instICCID ICCID of the profile just installed. This is the value the eSIM Profiles block's Enable input needs. Empty on failure.
errCode Reason the commit failed. See the enumeration at the foot of this table.
errCode Whatever reason was last recorded. Informational; abort itself does not fail.
Out Ev.
RDone Fires when the EID was read.
RFail Fires when it could not be read - no eSIM, or the modem is not up.
BDone Fires when the session is open.
BFail Fires when it could not be opened.
PDone Fires when the eSIM accepted the segment.
PFail Fires when it did not, OR when the hex was malformed. Treat this as 'abort and restart the package', never as 'retry this segment' - the authentication chain is already broken.
CDone Fires when the profile is installed. It is installed DISABLED - enable it via the eSIM Profiles block.
CFail Fires when the install was rejected. The session is aborted automatically so nothing is left half-installed.
ADone Always fires. Abort has no failure case by design - a cleanup that can itself fail is a cleanup callers will skip.
