SGP.32 Download Misc ↓ Params ↓ Ports ↓

Downloads a new subscription profile onto an eSIM using GSMA SGP.32 remote provisioning.

This is the only eSIM operation that needs a server. Managing profiles already on the chip needs no network at all - use the eSIM Profiles block for that.

The session needs IP reachability to the eIM / SM-DP+, but not necessarily over the cellular link. A factory line can carry it over Ethernet, Wi-Fi or a test fixture, which is what breaks the circular 'you need a network to get a SIM' problem.

A profile cannot be fetched now and installed later. The download is a mutually authenticated session in which the eSIM signs a challenge with its own key and the server verifies that specific chip; the resulting package is encrypted so only that eSIM can decrypt it, using session keys that a reboot destroys. So there is no staging a package to a file, and no preparing one device's profile and applying it to another.

Requires an eSIM chip and an SGP.32 provisioning stack. No currently supported target has either, so every operation reports not-supported (errCode 13).

Ports Top ↑ Misc ↓ Params ↑
In Ev.
SetEIM Configure the eIM (eSIM IoT Remote Manager) address that provisioning runs against. Set this before attempting a download.
Download Download and install the profile identified by the activation code.
Data In
eimAddress eIM server address. The one piece of configuration SGP.32 always needs, whether the provisioning agent runs on the device or on the eSIM itself.
activationCode Operator-supplied activation code identifying the profile to download.
Data Out
errCode Reason the download failed. See the enumeration at the foot of this table.
dlICCID ICCID of the profile that was just installed. A downloaded profile is installed but NOT enabled, so this is the value to feed into the eSIM Profiles block's Enable input - without it an app would have to list profiles and diff against a snapshot taken before the download. Empty on failure.
Out Ev.
EDone Fires when the eIM address was accepted.
EFail Fires when it was not - not-supported when no eSIM or no provisioning stack is present.
DDone Fires when the profile was downloaded and installed. Note it is installed but NOT enabled - enable it with the eSIM Profiles block.
DFail Fires when the download failed; see errCode.
