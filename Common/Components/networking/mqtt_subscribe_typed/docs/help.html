MQTT Subscribe Typed Misc ↓ Params ↓ Ports ↓

The MQTT Subscribe Typed block subscribes to an MQTT topic and parses the received payload as integer, float, and boolean values simultaneously, firing a received output event when a message arrives.

This block expects a text payload, not binary. It is intended for brokers and IoT platforms that carry numeric and boolean values as human-readable ASCII — for example Blynk, Node-RED, Home Assistant and most cloud dashboards, where the topic sensor/temperature carries the six characters "21.75" rather than a 4-byte float. The block reads that text and converts it to the ERT numeric types, so it saves wiring a separate string-to-number conversion block after every subscription.

For binary payloads, do not use this block. MQTT payloads are arbitrary byte arrays, and a value encoded as raw bytes needs a decoder that knows its word size and byte order. Use the untyped MQTT Subscribe block to obtain the payload and then the raw-data conversion blocks under Data Utilities → String Functions → Raw Data Conversion and Data Utilities → Conversion (Hex String to String, bool→int8, and related blocks) to decode it.

Note that the MQTT component family carries payloads as null-terminated strings, so a payload containing a zero byte cannot be represented end to end. Binary data should therefore be hex- or base64-encoded by the publisher before transmission.

All three typed output ports (value_i, value_f, value_b) are updated on every received message. The boolean conversion treats the strings "true", "True", or "TRUE" as true; "false", "False", or "FALSE" as false; otherwise a non-zero integer value is true. A payload that contains no digits yields zero on value_i and value_f — this is indistinguishable from a payload of "0", so the block does not signal a parse failure.

The Quality Of Service (QOS) level is an integer with three possible values: At Least Once (0), At Most Once (1), and Exactly Once (2).
