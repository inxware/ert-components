MQTT Publish Typed Misc ↓ Params ↓ Ports ↓

The MQTT Publish Typed block publishes a typed numeric or boolean value to an MQTT topic. Unlike the standard MQTT Publish block it accepts integer, float, and boolean input ports and converts the connected value to a string payload automatically.

The payload sent is text, not binary. An integer is formatted as decimal digits, a float in the shortest form that round-trips, and a boolean as the literal word true or false. A float of 21.75 therefore leaves the device as the five characters "21.75", not as a 4-byte IEEE-754 value.

This block is intended for brokers and IoT platforms that expect human-readable ASCII — for example Blynk, Node-RED, Home Assistant and most cloud dashboards. It saves wiring a separate number-to-string conversion block before every publication.

For binary payloads, do not use this block. MQTT payloads are arbitrary byte arrays, and a value encoded as raw bytes needs an encoder that knows its word size and byte order. Build the payload with the raw-data conversion blocks under Data Utilities → String Functions → Raw Data Conversion and Data Utilities → Conversion (integer→string (hex), Hex String to String, and related blocks), then send it with the untyped MQTT Publish block.

Note that the MQTT component family carries payloads as null-terminated strings, so a payload containing a zero byte cannot be represented end to end. Binary data should therefore be hex- or base64-encoded before publication.

Connect only one of value_i, value_f, or value_b. If more than one is connected the priority order is integer > float > boolean, and the lower-priority values are silently discarded.

The Quality Of Service (QOS) level is an integer with three possible values: At Least Once (0), At Most Once (1), and Exactly Once (2).
