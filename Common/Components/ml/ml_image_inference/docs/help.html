Image Inference Misc ↓ Params ↓ Ports ↓

Image Inference of image data input based on loaded model with vaiants like yolov8-seg. Hardware Acceleration is available for supported targets.

Ports ↓
Name Type Default Min Max Description
Model Type I 0 0 4001 The type of model loaded. Selects the post-processing pipeline for the inference output. 0 = auto/generic (raw inference only; output will be empty). Non-zero = filter: only this model type is accepted (e.g. 1003 for YOLOv5, 1006 for YOLOv8).
Model Format I 0 0 4 The format of the model file. 0 = auto-detect from file extension. 1 = TFLite (.tflite / .tfl), 2 = ONNX (.onnx / .onn), 3 = TensorFlow (.pb), 4 = Hailo (.hef). Non-zero acts as a filter: load fails if the file extension does not match.
Data Type I 0 0 16 The tensor data type for model input/output. 0 = auto-detect. 1 = uint8, 2 = int8, 3 = uint16, 4 = int16, 5 = uint32, 6 = int32, 9 = fp16, 10 = fp32, 11 = fp64.
HW Accelerate B 0 0 1 Enable hardware acceleration. Some platforms may not support it; an error is emitted if unsupported. Some platforms require a specific model format (e.g. Hailo requires .hef); an error is emitted if the wrong format is loaded.
Conf Thres F 0.5 0 1 Confidence threshold for detections. Results with a score below this value are filtered out. Range 0.0–1.0.
Thread Number I 0 0 16 Number of threads for inference. 0 = platform default. Ignored on platforms that do not support multi-threaded inference.
Use Application Dir B 0 0 1 Root directory for the model path. 0 = user data directory, 1 = application directory.
JSON Format I 0 0 1 Output JSON structure written to the json port.

0 — Object-based (default). Each detection is an object inside a "res" array. Fields have no numeric suffix. 
{"type":1,"det_cnt":2,"res":[
  {"cls":0,"lbl":"person","cnf":0.9200,"x":320.0,"y":240.0,"w":100.0,"h":80.0},
  {"cls":2,"lbl":"car",   "cnf":0.8800,"x":500.0,"y":300.0,"w":200.0,"h":120.0}
]}
1 — Flat. All detection fields are at the top level with a numeric index suffix. Useful for downstream blocks that cannot parse nested arrays. 
{"type":1,"det_cnt":2,
 "cls0":0,"lbl0":"person","cnf0":0.9200,"x0":320.0,"y0":240.0,"w0":100.0,"h0":80.0,
 "cls1":2,"lbl1":"car",   "cnf1":0.8800,"x1":500.0,"y1":300.0,"w1":200.0,"h1":120.0}
In both formats, x/y are the bounding box centre and w/h are width/height in pixels.
