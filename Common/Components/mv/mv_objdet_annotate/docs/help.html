Annotate (ObjDet) draws labelled bounding boxes onto a camera frame using the JSON detection output from ML Image Inference or TFLite Frame. Each detection gets a coloured outline box and an optional text label showing the class name and confidence percentage. The frame is modified in-place — pass its ID to Frame Show or save it with Frame Write File to see the annotations.

Box colour is keyed automatically from the object class ID using a built-in 16-colour palette that cycles for class IDs beyond 15. No configuration is required to get distinct colours for multi-class models.

The block accepts both JSON formats produced by ML Image Inference. All coordinates are pixel-space centre + width/height of the bounding box.

Object-array format (default, enable_flat_json=0):

{"type":1,"det_cnt":2,"res":[
  {"cls":0,"lbl":"person","cnf":0.87,"x":320,"y":240,"w":100,"h":80},
  {"cls":2,"lbl":"car",   "cnf":0.92,"x":640,"y":360,"w":200,"h":150}
]}

Flat format (enable_flat_json=1):

{"type":1,"det_cnt":2,
 "cls0":0,"lbl0":"person","cnf0":0.87,"x0":320,"y0":240,"w0":100,"h0":80,
 "cls1":2,"lbl1":"car",   "cnf1":0.92,"x1":640,"y1":360,"w1":200,"h1":150}

Coordinate semantics: x and y are the pixel coordinates of the box centre. w and h are the full width and height of the box. The block converts these to top-left / bottom-right corners internally. Detections with w=0 or h=0 are silently skipped. Up to 50 detections per frame are processed; extras are ignored.

Parameters

Ports ↓

NameTypeDefaultMinMaxDescription
box_thickness I2110 Outline thickness of each bounding box in pixels. 1 = thinnest single-pixel line. 2–3 recommended for 640×480 or larger frames. Values outside [1, 10] are clamped.
show_label B101 When 1, draws a text label above each bounding box containing the class name and confidence percentage (e.g. person 87%). When 0, only the coloured outline is drawn — useful when labels are too small to read at the displayed resolution.
copy_frame B001 Controls whether annotation is performed in-place or on a copy of the frame.
0 (default) — in-place: bounding boxes are drawn directly onto the input frame. No extra memory is allocated. Use this when the annotated frame is the only consumer downstream (e.g. pass to Frame Show or Frame Write File). Do not feed the same frame to ML inference after annotation in this mode — draw operations corrupt inference inputs.
1 — copy mode: the input frame is cloned into a private frame buffer before annotation. The original frame is left untouched and can continue to be used for further inference. The cloned (annotated) frame ID is output on annotated_frame_id. Uses additional memory equal to one uncompressed frame.
Ports Top ↑ Errors ↓ Params ↑ Colours ↑
annotate
In Ev.Type
run Triggers annotation. Reads the frame id and detections inputs, parses the JSON, and draws all bounding boxes onto the frame. Fires done on success (including when there are zero valid detections) or error on a hard failure such as a missing frame or unparseable JSON structure.
Data InType
frame id I Frame slot ID of the frame to annotate. Obtain from Camera, Frame Resize, Frame Crop, or another frame-producing block. The frame is modified in-place: its pixel data is changed by the draw operations. Do not feed this same frame slot to ML inference after annotation — draw operations corrupt inference inputs.
detections S Detection JSON string. Connect to the output port of ML Image Inference or TFLite Frame. Both the object-array format ("res":[...]) and the flat indexed format ("cls0":N,"x0":N,...) are accepted. See Detection JSON Formats for field details.
Out Ev.Type
done Fired when annotation completed — either boxes were drawn, or the JSON contained zero valid detections (det_cnt=0 or all detections had zero-size boxes). Check errno to distinguish.
error Fired when annotation could not proceed: invalid frame ID, frame not found, or missing JSON input. Connect errno to determine the specific reason.
Data OutType
errno I Result code. See Error Codes below. 0 means boxes were successfully drawn.
annotated frame id I Frame slot ID of the annotated output frame. The value depends on copy_frame:
  • copy_frame=0 (in-place): outputs the same ID as frame id — the original frame, now annotated.
  • copy_frame=1 (copy mode): outputs the ID of the cloned frame that was annotated. The original frame is unchanged.
On error, outputs -1. Always check for -1 before passing downstream.

  • The frame id input was not connected or carried a negative value (no frame available yet — check upstream block fires before annotate).
  • The frame slot ID was not found in the global frame pool (frame was destroyed or never created).
