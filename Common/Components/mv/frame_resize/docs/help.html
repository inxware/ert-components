Frame Resize Misc ↓ Errors ↓ Params ↓ Ports ↓

Frame Resize scales a camera frame to a new width and height and writes the result into a new frame buffer. The resized frame can then be passed to downstream blocks such as Frame Crop, Frame Format, Frame Show, or ML inference blocks, exactly like any other frame.

The target size is given by size_x and size_y (pixels). Both can be set as static parameters and/or overridden at runtime via the input ports. The interpolation method used for the scale is fixed per instance by the Interpolation parameter.

If both size_x and size_y resolve to zero the block fires err with errno 2 (UNUSED) and does not produce a resized frame. This lets you conditionally bypass resizing without disconnecting the block.

The block works on frames in any pixel format: default BGR (format 0), greyscale 8-bit (format 1), normalised 32-bit float single-channel (format 2), and normalised 32-bit float three-channel (format 3). Connect the output of Frame Format directly to Frame Resize when working with converted frames.

resize
In Ev.Type
run Triggers the resize operation. Reads the source frame identified by stream_id, scales it using the current size values and the Interpolation parameter, and stores the result in this block's private frame buffer. Fires -- on success or err on failure.
Data InType
stream_id I Frame slot ID of the source frame to resize. Obtain this from the stream_id output of Camera, Frame Crop, Frame Format, or another upstream frame block.
size_x I Runtime target width override. If connected, this value takes precedence over the size_x parameter for this invocation.
size_y I Runtime target height override. If connected, this value takes precedence over the size_y parameter for this invocation.
Out Ev.Type
-- Fired when the resize completed successfully. The resized frame is available on stream_id.
err Fired when the resize failed or was bypassed. Connect errno to determine the reason (see Error Codes).
Data OutType
errno I Error code set after each invocation of resize. 0 = success. See Error Codes below.
stream_id I Frame slot ID of the resized output frame. Only valid after -- fires. Pass this to downstream blocks (Frame Crop, Frame Show, ML inference, etc.).
Error Codes Top ↑ Misc ↓ Ports ↑ Params ↑

The errno output port carries one of the following values after each invocation of resize.

Value Name Meaning Common causes & remedies
0 OK Resize succeeded. — -- event fires.
1 FAILED Resize operation failed.
  • No valid source frame: the stream_id input is not connected or the upstream block has not yet produced a frame.
  • This block's internal frame buffer is not initialised (frame slot allocation failed at startup).
  • The HAL resize function returned an error (e.g. memory allocation failure, or an unsupported combination of size and format).
2 UNUSED Both size_x and size_y resolve to zero — resizing was skipped. Set at least one of size_x or size_y to a non-zero value, either as a parameter or via a connected input port. If zero-bypass is intentional, ignore this event or connect it to a pass-through path.
