Frame Crop Misc ↓ Errors ↓ Params ↓ Ports ↓ Coords ↓

Frame Crop cuts a rectangular sub-region from a camera frame and writes the result into a new frame buffer. The cropped frame can then be passed to downstream blocks such as Frame Resize, Frame Format, Frame Show, or ML inference blocks, exactly like any other frame.

The crop region is defined by two corner coordinates: (x1, y1) is the top-left corner and (x2, y2) is the bottom-right corner, both in pixels relative to the top-left of the source frame. Crop values can be set as static parameters and/or overridden at runtime via the input ports.

If all four crop values are zero the block fires err with errno 2 (UNUSED) and does not produce a cropped frame. This lets you conditionally bypass cropping without disconnecting the block.

The block works on frames in any pixel format: default BGR (format 0), greyscale 8-bit (format 1), normalised 32-bit float single-channel (format 2), and normalised 32-bit float three-channel (format 3). Connect the output of Frame Format directly to Frame Crop when working with converted frames.

Crop coordinates are pixel offsets from the top-left corner of the source frame, measured in the frame's native pixel grid (before any resize).

Value Meaning
x1 Left edge of the crop region (column offset). The cropped frame starts at this column. 0 = left edge of the source.
y1 Top edge of the crop region (row offset). The cropped frame starts at this row. 0 = top edge of the source.
x2 Right edge of the crop region (exclusive column). The output width is x2 − x1. Must be greater than x1 and no larger than the source frame width.
y2 Bottom edge of the crop region (exclusive row). The output height is y2 − y1. Must be greater than y1 and no larger than the source frame height.

Example: to crop a 1920×1080 frame down to a 640×480 region starting 100 pixels from the left and 60 pixels from the top: 

x1 = 100,  y1 = 60,  x2 = 740,  y2 = 540

This produces a 640×480 output frame (x2−x1 = 640, y2−y1 = 480).

All-zero bypass: if all four parameters and all four input ports are zero (the default), the block treats cropping as unused and fires err (errno = 2, UNUSED) without producing an output frame. This is intentional — it allows a crop block to be placed in a pipeline and effectively disabled by leaving the defaults.

Error Codes Top ↑ Misc ↓ Ports ↑ Params ↑

The errno output port carries one of the following values after each invocation of run_cropping.

Value Name Meaning Common causes & remedies
0 OK Crop succeeded. — -- event fires.
1 FAILED Crop operation failed.
  • No valid source frame: the stream_id input is not connected or the upstream block has not yet produced a frame.
  • This block's internal frame buffer is not initialised (frame slot allocation failed at startup).
  • The crop coordinates extend outside the source frame boundaries (x2 > frame_width or y2 > frame_height). Check that the coordinates match the actual frame dimensions.
  • The HAL crop function returned an error (e.g. memory allocation failure).
2 UNUSED All crop values are zero — cropping was skipped. Set at least one of x1, y1, x2, or y2 to a non-zero value, either as a parameter or via a connected input port. If zero-bypass is intentional, ignore this event or connect it to a pass-through path.
