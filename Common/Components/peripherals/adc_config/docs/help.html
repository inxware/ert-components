adc_config Misc ↓ Params ↓ Ports ↓ Channels ↓ Errors ↓

Configures an ADC unit before use with adc_read_single or adc_read_continuous. Trigger init once at startup. On success the finish event fires; on failure the error event fires and error_id carries a numeric error code (see Error Codes below).

Configuration may be supplied via block parameters or overridden at runtime via the JSON input port. If the JSON port is connected and non-empty when init fires, the JSON values take precedence over the parameters.

NOTE: Each ADC unit may only be configured once per run. Triggering init a second time on the same device_id fires the error event with error_id = -3 (already initialised). Continuous mode is not supported on all platforms — see Error Codes.

init Trigger to configure the ADC unit. Reads parameters (or the JSON input if connected) and calls the platform HAL to initialise the hardware. Fires finish on success or error on failure. Should be triggered once at startup before any adc_read_single or adc_read_continuous blocks that reference the same device_id.
Data In Description
JSON Optional runtime configuration string. When connected and non-empty, overrides the block parameters. Fields that are absent in the JSON fall back to the parameter values. Format:

{"id":0 ,"fs":1000 ,"m":0 ,"c0":-1 ,"c1":0 ,"c2":1 ,"c3":-1 , ... ,"c15":-1 }

Keys: id = device_id, fs = f_s_hz, m = mode, c0–c15 = channel slot mappings (-1 = disabled).
Out Ev. Description
finish Fired when the ADC unit was configured successfully. The unit is ready for use by adc_read_single or adc_read_continuous.
error Fired when configuration failed. Check error_id for the specific reason (see Error Codes).
Data Out Description
error_id Integer error code, valid when error fires. Zero means no error (will not be set on the finish path). See Error Codes for the full list of values. Connect to a variable or display block to capture the failure reason.

ESP32-S3 (IDF)

GPIO numbers vary by ESP32 variant — consult the ESP-IDF ADC documentation for your specific chip. At least one channel must be enabled; configuring a unit with all channels set to -1 returns error_id = -5.

Arduino

The channel value is the Arduino analog pin number (0 = A0, 1 = A1, …). Up to 4 channels (A0–A3) are supported by default; boards with EHS_TARGET_ADC_CHANNEL_NUMBER = 8 support A0–A7. Continuous mode is not available on Arduino.

Stubbed / SPI_A6_LTC241X

Channel values are accepted without hardware validation. Reads return 0. These targets do not produce error_id = -5 or -6 on init.

Error Codes Top ↑ Channels ↑ Ports ↑

When the error event fires, the error_id output port holds one of the following values (defined as ehs_adc_err_t in the platform HAL):

codenamemeaning / cause
0EHS_ADC_ERR_NONE Success. Not set on the error path.
-1EHS_ADC_ERR_NOT_SUPPORTED The adc_config block is not supported on this platform (the HAL predates the modern ADC API). Use the legacy adc_read block instead, or upgrade the HAL.
-2EHS_ADC_ERR_INVALID_DEVICE device_id is out of range for this platform. Check the maximum unit count in the platform HAL header (EHS_TARGET_ADC_UNIT_NUMBER).
-3EHS_ADC_ERR_ALREADY_INIT The specified ADC unit has already been configured. Each unit may only be initialised once per run. This error fires if init is triggered a second time on the same device_id.
-4EHS_ADC_ERR_FREQ_RANGE f_s_hz is outside the range supported by the platform (too low or too high). Adjust the parameter or use the JSON override port.
-5EHS_ADC_ERR_INVALID_CHANNEL One or more channel values are not valid for this board variant or MCU pin mapping. Check the Channel Mapping table for the target platform.
-6EHS_ADC_ERR_HAL_INIT_FAILED The hardware peripheral or sysfs node could not be initialised. On Sfera Labs targets this means a sysfs node was not readable — check that the kernel module is loaded (lsmod | grep ionopi etc.). On ESP32/Arduino this means the MCU ADC peripheral returned an error during setup.
